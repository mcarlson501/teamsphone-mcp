# Support

TeamsPhone MCP is experimental, pre-release software maintained on a best-effort basis.
There is no production support commitment or service-level agreement.

## Public questions

Ask setup, configuration, and usage questions through the
[public question form](https://github.com/mcarlson501/teamsphone-mcp/issues/new?template=question.yml).
Keeping support discussions public makes answers searchable and lets other users
contribute corrections or workarounds.

Before opening a question:

1. Read the [README](README.md) and the relevant guide under [docs](docs/).
2. Search [open and closed issues](https://github.com/mcarlson501/teamsphone-mcp/issues)
   for the same behavior.
3. Reproduce the problem with synthetic data and remove tenant or customer information
   from logs and examples.

Maintainers aim to acknowledge public questions within seven days when available. If no
one has responded after seven days, add one polite comment to the same issue. Response
times may be longer while the project is pre-release.

## Other reports

- Use the [bug report form](https://github.com/mcarlson501/teamsphone-mcp/issues/new?template=bug_report.yml)
  for reproducible incorrect or unsafe behavior.
- Use the [feature request form](https://github.com/mcarlson501/teamsphone-mcp/issues/new?template=feature_request.yml)
  for focused improvements.
- Report suspected vulnerabilities privately as described in
  [SECURITY.md](SECURITY.md). Never disclose a vulnerability in a public issue.
- Report conduct incidents privately as described in
  [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Never disclose a conduct report in a public
  issue.

## Data safety

Use synthetic data only. Do not post tenant IDs, tenant names, customer identifiers,
UPNs, real phone numbers, access tokens, signing keys, certificate material, PFX data,
private audit records, or unsanitized logs. Correlation IDs and minimal redacted result
envelopes are preferred when diagnostic context is necessary.
